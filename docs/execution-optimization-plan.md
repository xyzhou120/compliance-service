# 检查链路优化实施计划

2026-10-26。用户授权按以下顺序实施，以同一组真实附件比较耗时、资料覆盖和证据定位。

## 第一阶段：范围、收据、可见性

- 新任务显式 checkCycle 优先；省略时取 Asia/Shanghai 当前年月。历史已冻结查询不更改。
- Windows 收据原子写入做短退避及附件级恢复；下载、写收据、解析失败分别可见。
- 页面显示实际取数范围、最新文件/页、阶段计数；历史事件分页，停止重复读取首页事件。

## 第二阶段：业务处理顺序与识别

- stop_work_unload 优先阈值/防冲日报，再相关行动记录，最后补充设计/评价；不跳过必要资料，不以部分扫描证明通过。
- 识别做受限图片渲染、明确页预算、有限并发；独立来源比较和逐页证据定位保持。
- 每批保存阶段输出；预核验进度明确标为未定版。

## 第三阶段：执行与恢复

- API 仅受理和展示，独立 worker 领取持久任务；一个脚本管理两个进程。
- 页面/文件/provider 成功输出可复用；历史任务和结果不覆盖，失败单元单独重试。
- 缓存版本按实际行为版本化；不可因与解析无关的代码改动整体失效。

## 验证

- 回归：周期、附件身份、收据错误、租约、暂停/恢复、识别一致性、证据引用、查询分页。
- 固定真实样本：已有 13 份 2026-10-14 至 16 日附件，冻结 ID、路径和 SHA256。
- 每阶段原生解析对照；识别阶段比较相同真实页面、同一模型/预算、相同缓存条件；模型调用超时、缺页和不一致必须计入报告。
- 当前长任务不中途改写范围。发布新版本时在检查点暂停并由新 worker 恢复，保留输入与结果历史。
- 无真实完整性证明时不输出通过，结果仍按证据和缺口收束。耗时改善不是业务准确率验收。
