# 跨文件合规检查核心计划与进度更正

2026-10-23。平台以同一矿井、检查范围内的多份文件为输入，对事件建立跨文件证据链并执行两项合规检查。解析、OCR、模型取证、缓存和交付围绕这条主线建设。原计划T18–T26已经涵盖该能力，此处明确主线与实际实现边界。

## 当前进度

跨文件检查进入受限首版，未完成实矿验证。目前可以把DOCX中的事件、XLSX中的动作与指标、其他DOCX中的要求合并判断；同一工作面、同一原文日期、唯一精确时间段且无共同编号时也可生成内部候选事件标识。该关联仍带候选局限，不证明真实原始资料的因果归属已经完成。

真实文档没有共同事件编号、工作面写法不一致、措施跨期有效、阈值属于独立批复等复杂情况仍需补充验证。原进度中“M4两项规则已完成首版”应理解为规则算子和受限关联首版，M4整体状态仍为部分完成。

## 下一步开发顺序

1. T19/T20：同一资料范围内的全量事件线索与事实提取；不同文件重复利用共享解析产物，不能只查少数相似文档。
2. T21：依据可追溯的工作面/区域、名称对应关系与时间建立跨文件事件关联；无明确依据不强行拼接，冲突和未关联线索保留缺口。
3. T22：从独立设计、措施及批复中匹配事件适用的阈值、必要方法/测点和有效期，不要求所有原文件先统一事件编号。
4. T23–T25：逐事件对停工、断电、撤人、报告、卸压、检验、技术确认、调度解除和实际采掘建立支持、反证、缺口与时序；必要条件均有证据且覆盖成立才通过。
5. T26/T27：补报、替代、作废或阈值变化后重判旧事件，解释差异并输出跨文件证据链。首版允许复用解析后全量重判，避免提前引入复杂依赖平台。

OCR、视觉和语义模型按上述真实样本的取证需要接入，保留原文与定位，由规则校验候选。OceanBase和正式回调接入不替代本地真实跨文件检查验收。

## 两项检查的证据链

停工撤人与卸压：监测/动力现象记录中的触发 → 独立措施/批复中的适用要求 → 调度、停送电、撤人及报告的实际记录 → 危险研判与解危施工/验收 → 对照同地点生产记录形成判断。

解危效果检验：解危施工完成 → 必要方法/测点要求 → 原始检验指标 → 批准阈值与有效版本 → 技术负责人确认 → 调度解除 → 实际复工时序。每一步都可以来自不同文件，并保留支持与反证。

## 开发期验收

使用同矿真实材料分布于多份文件的样本，验证没有共同事件编号时仍能关联，并检查错矿、错工作面、同名不同事件、时间粗糙、不同阈值版本、缺关键资料、正面反证及旧事件补报。每个命题均可追溯到文件版本与页/行/单元格；资料缺失不能等同未执行，转引不算独立佐证。

这批开发样本直接推动核心准确性改进；复杂分层盲测仍留M6，不增加人工审批或人工修改pass/no_pass流程。真实样本验证结果与既有127项工程测试、合成文档案例分开报告。
