# 1023两项跨文件检查的暂行开发规则

本次以用户提供的冲击地压规则1023.xlsx为首要输入，源表AI深度监察第2、3行。原工作簿保持不变；登记为impact-1023-draft-v1。该表可以作为开发基线，无须等待所有业务口径定稿，但当前实现不能冒称整份规则已经完整检查。

## 两条核心检查链

第一项：适用区域和防冲要求 → 监测超限或动力现象 → 立即停工、断电、撤人、报告 → 危险研判 → 持续危险对应的卸压施工与验收 → 同地点实际采掘反证。

第二项：解危施工完成 → 效果检验任务和必要指标全集 → 原始测值与适用批准阈值 → 技术负责人确认 → 调度解除 → 实际复工。每一步可以来自不同文件，不能要求原文件预先填写相同事件编号。

## 建议明确的六处口径

| 原表位置 | 现有表述或缺口 | 本轮开发处理与后续建议 |
| --- | --- | --- |
| E2/F2 | 动力现象与危险研判连写 | 立即处置与研判后卸压分开；不能等日分析才开始核查立即响应。没有通用分钟阈值，不发明5分钟等默认期限 |
| E2/F2/E3/F3 | 通知、设备运行、查无记录容易混成实际行为 | 明确采掘、现场动作、指令与自述的事实类型；普通设备运行和检修不能独立证明采掘；查无记录为缺证 |
| F2/F3/H2/H3 | 疑似重大隐患与人工复核混在结论里 | 使用五类机器结果；具体问题、候选关联与缺口分别输出。暂不把所有no_pass定成重大事故隐患，不设服务内人工改判 |
| E2/F2、E3/F3/H3 | 时序和等于阈值边界 | 原表草案要求停工/断电不晚于撤人、解危施工，按必要偏序核对，不强排四动作串行。效果值等于阈值且已证明实际复工，可形成细则问题，但不能把重大隐患的“超过”改成“大于等于” |
| G3及E3首项 | 缺效果检验原始资料、适用设计/措施；检验数据集中放进钻孔验收记录 | 补充独立的效果检验/原始监测、适用方法和测点要求、阈值批复等资料角色；钻孔验收主要证明施工完成，不能代替检验指标 |
| F3首步及G2/G3 | 无编号关联、年度/周期资料的适用 | 关联必须保留地点和时间依据，多事件不能取第一条。措施/阈值按批准范围与有效期匹配，年/月/周上传频率不当成有效期 |

H2涉及300m边界时需按具体法条区分比较符。当前不把相邻独立距离判项扩成新的检查任务；未经证实的实际撤离范围仍属于未覆盖条件。

## 已落实的工程增量

1. rulebook.py与data/impact_1023_draft_v1.json保留原表B2:J3、文件SHA256、单元格位置及暂行解释。J列仅作原始示例留存，不能当作真实文件的检查结论。
2. 受理时记录ruleVersion和基线revision，参与活动任务身份；取证快照和结果继续携带版本、原表单元格及执行代码revision。
3. association.py允许原始事件编号为空，生成内部标识。仅在同工作面、同原文日期、精确时序形成唯一事件段时建立候选关联；粗日期、错面、跨日、多候选不强拼。
4. 明确工作面与起止有效期的独立阈值、指标全集可派生适用于多个事件，保留source_fact_id、证据和适用点；冲突版本全部保留，不自动选最新或最严。
5. 修复独立研判文件未参与带险作业判断的问题：先综合研判，再检查已证明的危险时段内采掘与卸压；未来研判不追溯证明更早采掘违法。
6. 按草案E2/F2增加停工/断电与撤人、解危施工的偏序命题，明确引用原表，不冒充新增法条或分钟要求。
7. event_evidence_chains逐事件输出命题、来源文件、字节版本、页/行定位和原文；关联依据在association_links中单列。

## 当前结果如何解释

- status：本轮整项结果。
- implemented_condition_status：目前已实现条件的判断，不代表整份草案均已核验。
- rule_coverage.full_rule_check_complete：仅当全部能力已实现、资料和事件归属完整、所有命题闭合时为true；缺字段或候选关联仍为false。all_required_checks_implemented表示算子是否齐备，不能代替本轮证据完整性。
- association_assessment：是否使用同日时间候选关联及其局限。
- candidate_findings：依赖未证实事件归属的问题候选，不当作确定违规。
- findings：有独立明确证据支持的问题；不被其他未覆盖条件吞掉。

当前已增加危险性评价/设计范围、卸压类型/参数/验收、撤人和解危限员/设备、研判签字告知以及技术确认签字的事实核验。角色名或“已完成”不能替代这些字段。签字核验指文档中签署人、身份和时间证据，不声称数字证书密码学鉴真。资料完整且所有条件满足时两项均可pass，缺字段pending，明确反证no_pass。候选关联不独立支持确定结论，服务仍无人工改判。

两项规则算子仍在rules.py执行。JSON负责原表留存、版本选择和解释追溯，并非可以执行任意Excel文字的通用DSL。后续比较符、条件组合或必要证据改变，应新增规则版本，修改对应算子/参数和回归用例；不覆盖历史结果。精确复算还需要对应执行代码和输入版本，不能仅凭一份JSON声称可重现旧逻辑。

## 调试方式

```json
"ruleVersion": "impact-1023-draft-v1"
```

不填写时新本地文件任务选用当前登记的暂行版本；fixture模拟模式不使用该业务规则本。GET /v1/definitions可查看登记版本，结果可追溯原表F2/F3。

下一步用真实多文件样本验证各字段在实际版式中的提取。OCR和视觉provider已接入本地配置；转录候选需通过一致性、事实和规则校验，复杂自由文本、别名和跨日歧义仍应保留缺口。无需增加通用图平台、人工审批或最终分层盲测。
