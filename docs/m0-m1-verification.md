## 独立复评

两路独立审阅按用户最新边界放行开工：删除人工改判和 review_state；受理范围键与实际文件快照分开；用持久账本、租约和证据归属验证流程。复杂分层盲测留 M6，外部网络安全在真实接入阶段完成。

实现后两路独立复核发现并复现两项问题：必要命题缺项仍可能 pass；普通处理异常会退出 worker，阻塞其他项。已先补回归复现再修复：从定义登记核对必要命题全集；普通异常持久化 failed 和错误阶段，其他项继续；真实崩溃恢复超过3次时收束，过期 fence 不允许发布技术失败。独立再次复验，两项均闭环，无剩余本地 M1 阻塞。

## 最终验证

本轮收尾验证使用 Python 3.12.4，命令 `python .omx/reviews/2026-10-23/verify_m1.py`（从工作区根目录）。

- 38 项 unittest 全部通过，含 HTTP、SQLite 并发/事务/租约、执行与交付故障、证据归属、五类终态和禁止真实 socket 调用。
- compileall 编译检查通过。
- `pip wheel --no-deps --no-build-isolation --no-index` 离线构建 wheel 成功，未安装新依赖。
- 在临时空目录仅将 wheel 加入 PYTHONPATH，确认实际导入来自 wheel；默认 init 自动创建本地数据库。
- 独立 wheel 中逐一运行五种合成场景，两项检查分别得到预期五类结果并 mock delivered；无需本项目源码目录或旧 document-parser。

原始日志和机器可读摘要位于 `.local/verification/`，包括 tests.log、build.log、independent-*.log、summary.json；该目录已忽略，避免把运行数据库和临时证据混入源代码。

当前环境没有专门 lint/typecheck 工具，未运行这些工具，不将 compileall 或 unittest 称为类型检查。GitHub workflow 仅提供独立项目 CI 骨架，本轮未发布仓库或执行远端 CI。

## 实施内容

`contracts.py` 定义登记、范围身份、请求和证据归属；`ledger.py` 持久账本与同事务 outbox；`fixtures.py` 合成资料和必要命题聚合；`service.py` 共用受理/执行/交付用例；`api.py` 双入口与只读结果查询；`__main__.py` init/demo/worker/serve；三个测试文件与独立安装描述 pyproject.toml。

采用两个状态维度与不可变结果；未增加人工审批、人工改判、生产队列、外部模型或网络治理流程。SQLite 待办轮询用于本地单机验证，后续唤醒队列不改变账本语义。

## 保留的验证边界

- 当前两项定义和解析均是 engineering-mock-v1；未实现真实 PDF/XLSX/DOCX/OCR 抽取或正式法规判断，不能据此报告准确率。
- 恢复证明来自故障注入、模拟时间和 SQLite 重新打开，尚未验证物理断电或实际强杀进程后的生产恢复。
- 未联调 OceanBase 方言/只读权限、真实附件、S3/MinIO、正式上游报文/回调及远端去重。
- 本机查询条件只验证来源/矿井/运行归属，不代替生产可信鉴权；长耗时任务自动续租和多机数据库能力待后续适配验证。
- T04 当前提供工程定义样例与显式 fixture 范围；正式清单映射、周期含义、阈值选择和法条组合仍需在真实业务发布前确定。
